## السبب

فيه نوعين للنص في Rust، وهما مش نسختين من نفس الحاجة — دول حاجتين مختلفتين
فعلاً في الذاكرة.

`"hello"` اللي بتكتبها كده في الكود اسمها **string literal**، ونوعها `&str`.
الحروف بتاعتها مكتوبة جوه الملف التنفيذي نفسه وقت الترجمة، فهي موجودة طول عمر
البرنامج، ومينفعش تتغير، ومحدش بيملكها. اللي بيتحط على الستاك حقلين بس — عنوان
وطول، 16 بايت.

`String` حاجة تانية خالص: نص محجوز على الهيب، بيملكه متغير، ينفع يكبر ويتغير.
اللي بيتحط على الستاك تلات حقول — عنوان وطول وسعة، 24 بايت.

الكومبايلر مش بيحوّل بينهم لوحده، لأن التحويل مش مجاني: `String` من `&str` معناه
حجز على الهيب ونسخ للحروف. لو ده حصل ضمني، كنت هتدفع التكلفة دي من غير ما تشوفها
في الكود.

## الحل

**من `&str` لـ `String`** — دي هي اللي بتكلّف، لأنها بتحجز:

```rust runnable
fn main() {
    let a: String = "hello".to_string();
    let b: String = String::from("hello");
    let c: String = "hello".into();

    println!("{a} {b} {c}");
}
```

التلاتة بيعملوا نفس الحاجة بالظبط. `String::from` هي الأوضح للقارئ الجديد.

**من `String` لـ `&str`** — دي مجانية، مفيش نسخ:

```rust runnable
fn takes_str(s: &str) {
    println!("{s}");
}

fn main() {
    let owned = String::from("hello");

    takes_str(&owned);
    takes_str("literal");
}
```

## القاعدة العملية

**في الباراميترات، خد `&str` مش `String`** — إلا لو الدالة محتاجة تملك النص فعلاً.

الدالة اللي بتاخد `&str` تقدر تستقبل الاتنين: literal على طول، و`String` بـ `&`
قدامها. الدالة اللي بتاخد `String` بتجبر كل حد بينده عليها إنه يحجز على الهيب،
حتى لو مكانش محتاج.

```rust
fn good(name: &str) {}      // بتقبل "world" و &owned
fn limiting(name: String) {} // بتقبل String بس
```

خد بالك إن رسالة الخطأ نفسها في المثال التاني فوق بتلمّح لده: بتقولك
`this parameter takes ownership of the value` وبتقترح تغيّر نوع الباراميتر.

## ليه بيحصل ده

الفرق ده مش تعقيد زيادة — هو نفس الفرق بين الستاك والهيب اللي كل حاجة في Rust
مبنية عليه. `&str` استعارة لحروف موجودة في مكان تاني، و`String` ملكية لحروف على
الهيب.
